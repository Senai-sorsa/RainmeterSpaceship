## B. HWiNFO shared memory with Windows fallback (not started)

Goal: hardware sensor values come from HWiNFO's shared memory when HWiNFO runs. Without it, the host shows only what Windows provides.

Steps:
1. Define `ISensorSource` in `ShipCore.Core` with one method that returns named readings. Modules depend on the interface only.
2. `HwinfoSharedMemory`: read-only open of HWiNFO's mapping. Check the mapping name and struct layout against HWiNFO's SDK documentation first (use Context7 or the vendor docs; do not guess the layout). Read-only, bounded reads, validate counts and offsets before reading.
3. `WindowsSensorFallback`: CPU, RAM, disk, network from Windows counters, with no HWiNFO dependency.
4. `CompositeSensorSource`: uses HWiNFO when available and otherwise falls back. Each reading records its source.
5. Tests: fake HWiNFO memory built as a byte array in tests, and the fallback path with HWiNFO absent. No real mapping opened in tests.
6. Mapping to skin measures: the 1902 `Measure=Plugin` lines in `Skins\Spaceship` are the parity target. Record which ones fall back.

Risk: HWiNFO's layout and version. A wrong read gives wrong numbers, so it must be checked against a live HWiNFO run, which needs the user's go. Until then the code is fake-tested only.
